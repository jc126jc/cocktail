## 1. 功能范围与原则

### 1.1 后台 AI 配方导入助手

- 将用户粘贴的既有中文/英文酒谱解析为结构化配方草稿。
- **禁止**空语境凭空生成配方。
- 所有结果须人工确认后才能保存；保存仅为普通草稿，发布走现有流程。
- 首版仅纯文本粘贴；不做 PDF / 图片 / OCR。

### 1.2 前台 AI 文本助手

0. **意图分流（先于检索）**  
   - `search`：用户在找酒、筛条件、点名配方、问「有没有…」「推荐…」等。  
   - `non_search`：寒暄、玩笑、无关话题、纯闲聊、明显不是在检索本地库（例如「尽可能难喝的酒」若仅为玩笑且无具体可映射条件，按 non_search；若明确要「推荐难喝/怪味」且可当作偏好检索，可判 `search`——**默认：无明确找酒意图 → non_search**）。  
   - `non_search`：短文本回复即可；**禁止**默认空条件库检索；**禁止**临时生成配方；可轻引导「可以说酒类/风味/酒名」。  
1. 仅 `search`：优先从本地库检索已有配方；展示条数按与首页相同的齐全优先补足规则，**上限 6 条**（首页仍为 12）。
2. 结合酒柜，优先齐全，其次缺 1–2。  
3. 结构化检索结果为 **0** 时，才临时生成配方文本。  
4. 临时结果仅文本展示，**无**入库入口。  
5. 必须标注「这是临时写的，还没核对过」。
6. 可含完整材料、用量、步骤。  
7. 可将酒柜作偏好，尽量用已有材料，**不得**声称一定齐全。  
8. 生成只能使用库中已有标准材料。

聊天与导入中间态均只在浏览器会话（前台聊天用 `sessionStorage`）：站内跳转可保留，关闭标签页即失；不落 SQLite。

## 2. 技术选型

| 项 | 值 |
| --- | --- |
| 服务商 | 硅基流动（可换） |
| 默认模型 | `deepseek-ai/DeepSeek-V4-Flash` |
| 封装 | 可替换 Provider Adapter |
| 环境变量 | `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` |

**不用**：LlamaIndex、ChromaDB、向量库、完整 RAG。  
SQLite 仍是正式数据唯一事实来源。  
AI 须联网；断网或无 Key 时：核心查询/酒柜/后台离线可用；AI 入口禁用并提示。  
API Key 仅服务端环境变量；禁止进前端、浏览器存储、SQLite、日志、API 响应。

## 3. 后台向导与流程

入口：后台「新建配方」旁 → **从原文导入**（独立向导，不嵌编辑页）。

1. 填来源、贴原文 → 2. LLM 结构化 JSON → 3. Schema 校验 → 4. 确定性单位换算 → 5. 确定性材料匹配 → 6. 未匹配再 AI 候选 → 7. AI 家族/风味建议 → 8. 人工审核 → 9. commit 为草稿 → 10. 现有发布。

再解析：每次新临时结果；展示差异；用户确认后才覆盖当前临时草稿；禁止静默覆盖。

### 调用限制

- 原文 ≤ 10,000 字符。  
- 失败自动重试 1 次；仍失败保留原文可手重试。  
- 首版无审计日志、无应用层频控（公网/多用户须重评）。

## 4. 结构化输出（摘要）

固定 JSON Schema，字段至少含：`name_zh` / `name_en`、`source`、`ingredients[]`（含 `raw_*`、`amount_ml`、`estimated_amount_ml`、`role`、`either_group`、`mapping`、`uncertain`）、`glassware`、`garnish`、`steps`、`suggested_family_id`、`suggested_flavor_ids`、`uncertain_fields`。

材料角色：`required` | `optional` | `garnish` | `either`；无法确认须标待确认，不得默认全 `required`。

## 5. 单位

- 盎司、厘升等：确定性程序转 ml，不靠 AI 算术。  
- 非体积（dash、个、适量等）：保留会话内原始量与单位；AI 可写 `estimated_amount_ml` 并标「AI 估算」；确认前正式 `amount_ml` 为空；用户确认后才写入 `amount_ml`。  
- commit 后不持久化整段原文、原始单位、AI 过程；只保留最终标准化配方 + 正常来源字段。

## 6. 杯具与装饰

混合映射：优先枚举/标准材料 → 否则自由文本 + 待确认。AI 不得直接创建新枚举或装饰材料。

## 7. 材料匹配

确定性优先：标准中英名、别名、大小写/空格/标点/括号归一化、已维护品牌别名、材料父子层级。禁止盲目剥品牌词。  
仅失败时 AI 候选：最多 3；须为库内 ID；置信度 ≥0.8 可预选但仍须审核；&lt;0.8 强制手选。不得自动建材料/父子；本次映射不写正式别名表。

## 8. 家族与风味

建议须落在现有 families / flavors；禁止发明标签；可不选；草稿可缺分类；**发布**前须补齐。

## 9. API

后台（须管理员会话）：

```text

POST /api/admin/ai-import/reparse
POST /api/admin/ai-import/commit
```

```text

```

工具（服务端确定性）：`search_recipes`、`get_recipe`、`check_inventory`、`calculate_missing_ingredients`、`list_standard_ingredients`、`get_inventory`。

## 10. 临时生成规则

仅 `search` 且库检索 0 条时；只用标准材料；显著警示；不伪造来源/经典权威；无保存入口；不参与正式齐全判断。`non_search` 不得进入本节。

### 10.1 聊天响应 kind

| kind | 何时 | UI |
| --- | --- | --- |
| `reply` | `non_search` | 仅助手短文本 |
| `library` | `search` 且库 ≥1 | 卡片 + 详情链 |
| `generated` | `search` 且库 0 | 临时文本 + 警示，无保存 |

## 11. 分期

| 阶段 | 内容 |
| --- | --- |
| P-AI1 | Provider、解析 Schema、单位、角色、杯具装饰初解析、再解析差异、commit 草稿 |
| P-AI2 | 确定性材料/杯具装饰映射 + 审核 UI |
| P-AI3 | AI 候选（≤3、0.8 预选）、家族/风味建议、完整审核 |
| P-AI4 | 前台聊天：意图分流、NL→条件、工具检索、零结果临时生成、警示 |

验收语料（后台）：10 IBA 英文 + 10 中文 + 用户 3–5 份代表原文。前台以人工试用验收。

## 12. 边界

AI：理解文本、意图分流、草稿结构、候选映射、分类建议、前台 NL、零结果临时文本。  
确定性代码：酒柜/缺料/筛选/层级/可靠单位换算/DB/发布校验/事务。  
未经人工确认不得进入正式配方库。
